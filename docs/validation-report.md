# Windows 本地验收报告

日期：2026-10-17。范围：固定 klogg 源码快照上的超长行可靠性改进。

交付包括实际应用源码、23 个生产文件的补丁、可运行 Windows 构建、确定性样例生成器、独立参考程序和回归证据。不是从零实现查看器，也不声称复现了历史 macOS 用户的原始环境；M0 使用独立同类反例。

## 基线反例

| 场景 | 固定上游基线 | 候选行为 |
| --- | --- | --- |
| 128 行压缩块相对跨度达到 2³² | 组件探针异常退出；实际 5 GiB 文件索引同样退出 | 大跨度使用 64 位存储，实际末行读回 1 字节且值为 10 |
| 高于 4 GiB 的绝对偏移、块内跨度较小 | 本来就通过 | 保持通过；没有混淆绝对偏移与块内跨度 |
| 空索引范围、移动后继续追加 | 空范围异常、移动重用破坏偏移 | 空范围、移动/自移动和重用回归通过 |
| 64 MiB 无末尾 LF 的单行原始读取 | 返回 67,108,865 字节，多出合成 LF；发生整行分配 | 读取钳制到实体 EOF；GUI 使用有界窗口 |
| 16 MiB 单行真实视图换行 | 约 40 秒后 bad allocation；采样峰值 private bytes 52,581,208,064 | 异步窗口与共享文本支撑可见行渲染，见下方最终测量 |

基线的 private bytes 是进程私有提交量，不能等同为物理内存 RSS。之后探针加入资源限额，未再次放任基线的大分配。

5 GiB 指 5,368,709,120 个实体字节。完整搜索样例 SHA-256 为 `93ef93929545c35396d2b3c9d58860a68dd2ad59243e99d5182318384d64d35a`；压缩跨度样例为 `8d86b95b1ca98ef5832330f7bab9dc0c950ec5167d5c56d16582176fbf686a0f`。runner 在每次运行前后校验输入哈希。

普通日志使用 134,259,979 bytes、1,118,481 行、11,185 个匹配行的固定样例。最终 **5 对交错运行**，每一轮完整匹配集合均通过独立 oracle；没有并行编译或其他本任务测试。两端使用相同 Qt 后端和 4 线程配置，操作系统文件缓存未清空。

## 支持范围与未覆盖项

长行路径要求非空、区分大小写、无预过滤的 UTF-8 字面模式；模式最多 1 MiB UTF-8 字节，不允许 LF，CR 作为内容保留。UTF-8 非法输入、长行正则/布尔/反向匹配及其他编码明确拒绝。普通文件继续使用既有匹配引擎。

预览每行窗口最多 16 KiB，单帧原始读取最多 128 KiB、最多 256 行。GUI 标注窗口字节范围，搜索命中跳转使用绝对字节位置并换算显示列。整条超长行复制、Quick Find 和旧式导出明确拒绝；窗口内的部分选择仍可复制。

128 MiB 是活跃搜索数据通路的保守租约预算，涵盖生产、排队、匹配和待合并块；不是 RSS 上限。索引、普通搜索累计结果、正则引擎内部空间和分配器保留内存另计。普通正则调用不因此获得严格取消时限。

未覆盖 Linux、macOS、Hyperscan/VectorScan、网络文件系统、所有编码及完整应用 sanitizer/竞态检测。未注入每个分配点的失败。相同文件身份、大小和时间戳下的外部原位修改不构成原子一致性保证。性能数据不是跨机器 SLA。
