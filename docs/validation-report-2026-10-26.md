## 本轮工具与探针修复

`tools/prepare_baseline.py` 现在对 ZIP 路径做跨 Windows/POSIX 的安全校验，并逐项核对解压后的文件集合与内容哈希，拒绝重复路径、缺失文件和额外文件。`tools/export_patch.py` 通过无 Git 历史的源码快照导出补丁，并在隔离副本中应用后逐文件重建校验，保留原始行尾；旧式 CRLF 导出曾出现 `git apply` 退出码为 0、但两个文件哈希不一致的情况，不能作为有效交付。当前 full patch 重建了 658 个文件并通过校验。

`tools/package.ps1` 会记录实际源码指纹、Git 工作树状态、构建参数和产物哈希；拒绝覆盖既有包目录或 ZIP，并核对补丁与刚构建源码一致。它不会把工具脚本的本地改动冒充为上游生产源码变更。此前遗留的诊断包不作为当前交付包。

独立审查还发现导出参数 `--output foo.json` 会与报告路径冲突，现已在写入前拒绝，并通过新增的参数回归断言；原有 `.patch` 运行包不受该边界问题影响。

CI 日志复核另外暴露出完整性校验器只检查历史日期目录的遗漏。新增反例先确认新日期的证据被计为零，随后扩展校验到所有日期目录的导出清单，保留必需的历史来源链；新增回归覆盖新证据计数、内容被修改和跨目录路径。最终 Python 测试为 49 项通过，本轮新导出的证据也纳入 CI 校验。

原生测试与探针的本轮增量包括：将受测配置读取改为不触发持久化重载的 `Configuration::get()`，避免测试重载配置时重新开启文件 watcher；为 follow 用例明确检查 watcher 与 polling 关闭；修复空文件搜索探针对有效行号的错误前置要求，并增加空文件搜索 CTest；GUI 探针现在拆分构造、字体、更新、显示等初始化阶段计时，并可选记录慢事件投递。工具和探针变化可在工作树的 `tools/`、`tests/native/` diff 中复核。

中间失败也保留为失败证据：空文件用例最初被对照编排器拒绝，后续探针又曾因错误行号要求而退出；一次 CTest 失败来自字面搜索用例重载持久化配置、重新启用 watcher。修复后对应本地检查通过，但这些修复不改变生产源码。

## GUI 首次建窗失败与诊断

**AC11 仍未通过本轮验收，且尚未重新确认 AC11 的全部子项。** 首次 Windows QPA 5 GiB 真实视图运行报告的最大 GUI 心跳间隔为 `862.0026 ms`，超过 PRD 固定的 500 ms 目标；视图销毁、真实锚点阶段完成不抵消该失败。该次验收汇总因此为 `failed`，不能表述成完整验收通过。

后续诊断把初始视图设置分解计时：5 GiB 文件场景 `show()` 为 `555.5866 ms`，1 MiB 文件场景 `show()` 为 `555.9905 ms`；两者的整体 `view_setup_and_initial_paint` 阶段分别为 `724.7903 ms` 与 `688.5101 ms`。Windows 上空 `QWidget` 的同步 `show()` 为 `246.4651 ms`，空 `QAbstractScrollArea` 为 `280.3875 ms`；offscreen 空窗仅 `0.5739 ms`。这些是诊断测量，不构成已定位根因的证明。空控件显示也不能替代实际产品窗口验收。不得降低 500 ms 阈值，也不得把诊断重跑解释为实际 GUI 已通过。

AC11 在此仍是开放项：需继续定位实际建窗停顿，并对冻结目标涉及的资源和交互项目取得足够证据后再做 AC11 整体验收。当前材料未证明所有 AC01—AC12 均在本轮重新核验；因此没有“完整验收通过”的结论。

固定上游基线在相同 1 MiB 文件的首次建窗也出现 `563.1172 ms` 心跳间隔。最终增加事件跟踪的 5 GiB 诊断仍失败：最大心跳 `575.6139 ms`，`show()` 为 `493.2234 ms`，记录的最慢事件投递约 66.03 ms；锚点跳转、启用换行、关闭换行的心跳分别约 12.71 / 23.12 / 17.11 ms。一次 1 MiB 诊断低于门槛并不抵消这些失败。系统 WPR 采样未能启用（`0xc5585011`），未修改系统策略。具体等待原因未确定，继续由 [问题 #9](https://github.com/Die4U23/klogg-longline/issues/9) 跟踪。

额外的自建子进程栈采样取得部分 Qt 图形初始化和 Windows 输入框架路径，但符号不完整，且在子线程退出时返回采样失败，不能证明完整耗时归因。一次使用 `QT_OPENGL=software` 的诊断也仅用于探索；该变量是 [Qt 官方提供的运行时选择](https://doc.qt.io/archives/qt-6.7/windows-graphics.html)，本轮没有将它写入产品或系统配置。没有据这些诊断改变默认路径的验收结论。

## 证据类别与支持边界

本报告中的基线身份、候选结果和性能对照分别来自独立基线探针、当前候选探针及五对普通日志测量，不合并基线、候选与诊断数据。历史报告中的旧测量只作为历史记录；不得用旧 GUI 通过数值覆盖本轮 `862.0026 ms` 失败。当前 GUI 原始证据与分阶段诊断分别存于 `.local/evidence/release-20261026-accepted/` 和 `.local/evidence/release-20261026-gui-diagnostic/`；剩余检查、性能试验、包校验和交付中间失败分别在 `.local/evidence/release-20261026-remaining/`、`.local/release-20261026/`、`.local/evidence/release-20261026-delivery/`。

本轮未运行 Linux 或 macOS 原生验收，未运行完整应用的 AddressSanitizer/竞态检测，也未重新覆盖 2026-10-17 历史报告列出的所有 AC。此前的索引组件 sanitizer 结果不代表完整应用。远端 CI 与合并结果以 [交付问题 #8](https://github.com/Die4U23/klogg-longline/issues/8) 关联的 PR 及 Actions 为准，不能从本地检查推断。

可审查的精简记录、原始文件哈希、测试输出尾部和复现脚本见 [证据清单](../evidence/windows-2026-10-26/manifest.json)。原始大日志和大样例保留在 `.local/`。证据目录中的 `current-run` 依然记录 `failed`，`remaining-checks` 的通过只覆盖普通日志对照及工具测试。`gui-*` 分别保留基线、首次失败、分步诊断和事件诊断，未覆盖或更名为最终成功。

符合 PRD 的支持契约仍有限：搜索主张仅针对其列出的 UTF-8 字面路径和固定样例；普通日志对照不等于所有数据与机器的性能保证。5 GiB 活跃缓冲测量不等于进程 RSS；窗口局部正确性不推出 Windows 启动流畅性。当前主要未关闭证据是 AC11 的真实 Windows 首次建窗停顿及完整 AC11 复核。
